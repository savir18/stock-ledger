Slide 12 (2 minutes). This is where InnoDB earns its place. Session A locks the balance row with SELECT FOR UPDATE. Session B asks for the same row and simply waits, because InnoDB locks at row level, so other products are not blocked. A inserts its sale and commits. Only then does B get the lock, see that stock is now zero, and get refused. The four boxes at the bottom are ACID, the properties InnoDB provides: atomic, consistent, isolated, durable. Mention the project has an automatic test where two sessions race for the last units and exactly one wins. In the live demo, the optional two-window locking demo shows this.
