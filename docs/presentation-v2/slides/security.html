Three guards

1. Passkey. Salted SHA-256 hash in a separate schema the web account cannot read.

2. Flask. Checks the role on every route.

3. MySQL. The procedure checks the role again. The web account can only read and execute.

Slide 10 (1 minute). On the sign-in screen you pick a role and enter its passkey. Passkeys are stored only as salted hashes in a separate schema, and five wrong tries lock that address for five minutes. Flask checks the role on every request, and MySQL checks it again inside the procedure, so even a bug in the web layer cannot post an entry the role is not allowed to. The web account has only SELECT and EXECUTE, so SQL injection cannot write to a table.
