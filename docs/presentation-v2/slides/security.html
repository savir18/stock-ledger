Slide 20 (1.5 minutes). Follow a sign-in left to right. The browser sends a role and a passkey. Flask hands it to sp_login, a procedure that is the only thing allowed to read the separate stock_ledger_auth schema, where passkeys exist only as salted SHA-256 hashes. After sign-in Flask keeps a signed session, checks the role on every route, and blocks an address after five wrong tries in five minutes. When data is written, the database account the web app uses can only read and execute, so even SQL injection could not alter a table, and the procedure checks the role a second time with fn_role_can. Two independent checks, so a bug in one layer is caught by the other. The passkeys in the demo are placeholders that the Admin page can change.
