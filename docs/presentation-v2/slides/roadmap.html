How it was built

Six steps in order. Each one rests on the step before it.

Step 1

Data model

12 tables around one ledger, with checks on every column.

Step 2

Triggers

Four triggers make the ledger append-only.

Step 3

Procedures

Every write is one transaction with locks.

Step 4

Analytics

Window functions answer questions about the past.

Step 5

Speed

Indexes and partitions, checked with EXPLAIN.

Step 6

Dashboard

Role and passkey sign-in on a Flask app.

The dashboard comes last on purpose: by then the database already enforces every rule.

Third, stored procedures so every write is one transaction. Fourth, analytics with window functions. Fifth, speed: indexes and partitions, proved with EXPLAIN. Sixth, the dashboard. The order matters: because the rules live in the database, the web layer can stay thin and no bug in it can break the ledger.
