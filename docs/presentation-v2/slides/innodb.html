The engine

What InnoDB gave the project

Transactions

A transfer is two ledger rows and two balance updates. All happen, or none do.

Row locks

FOR UPDATE locks one balance row, so only one sale can take the last unit.

Clustered key

Rows are stored in key order, so range reads on the ledger are fast.

Partitions

Quarterly slices let a monthly report read one partition. The trade-off: no foreign keys.

Slide 6 (1.5 minutes). InnoDB is the MySQL storage engine, and four of its features carried the project. Transactions make transfers all-or-nothing. Row locks stop two people selling the last unit. The clustered primary key keeps ledger rows in order. Partitioning splits the ledger by quarter, though InnoDB does not allow foreign keys on partitioned tables, so a trigger validates references instead.
