The dashboard can only call a procedure. The procedure does the rest in one transaction.

#StepWhat happensWhy it is safe
1CallDashboard runs sp_record_movementNo direct table writes

3LockLocks the balance row, FOR UPDATEInnoDB row lock

If any step fails, nothing is saved. The user sees a plain message such as Insufficient stock.

Slide 10 (1.5 minutes). Follow one sale through six steps. The key idea: the web account is only allowed to run procedures, never to write tables, so every write takes this exact path. Step two is the role check inside MySQL. Step three is the lock: the balance row is locked so no other sale can read the same quantity at the same time. Steps four and five insert the row and update the totals. Step six commits, or rolls everything back if anything failed. The live demo shows this working and then failing safely.
