Security

Least privilege, enforced in two layers

Layer 1: MySQL privileges

The dashboard logs in as ledger_app: SELECT and EXECUTE only.

No INSERT, UPDATE, DELETE, DROP or TRUNCATE on anything.

Four MySQL roles: ledger_admin, ledger_warehouse, ledger_purchasing, ledger_analyst.

Layer 2: business roles in the procedures

AdminEverything
Warehouse ManagerSale, return in, write-off, adjustment, transfer

Slide 11 (about 45 seconds). Two layers. First, real MySQL privileges: the account the web app uses can only read and execute. Even a bug or SQL injection in the dashboard could not write to a table directly. Second, business roles checked inside the procedures by fn_role_can, so each user type can only post the entries that suit their job. Third, each role signs in with its own passkey, stored only as a salted SHA-256 hash in a separate schema the web account cannot read. Live demo: sign out, sign in as Analyst (VIEWER-2468); the Record a change page is not offered, and a forced call is refused by the database. Optionally open a mysql prompt as demo_analyst and call sp_record_movement.
