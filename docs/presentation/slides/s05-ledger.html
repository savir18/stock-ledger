The ledger table

Built for appends and for history queries

CREATE TABLE stock_ledger (

ledger_id BIGINT AUTO_INCREMENT,

entry_time DATETIME(6) NOT NULL,

product_id INT, warehouse_id INT,

type_id TINYINT, user_id INT,

quantity_change INT NOT NULL,

unit_cost DECIMAL(12,2),

supplier_id INT NULL, transfer_id INT NULL,

reverses_ledger_id BIGINT NULL,

PRIMARY KEY (ledger_id, entry_time),

CHECK (quantity_change <> 0)

) PARTITION BY RANGE (TO_DAYS(entry_time));

Composite primary key

MySQL needs the partition column inside every unique key.

No foreign keys

Not allowed on partitioned InnoDB tables. A trigger checks every reference.

4 indexes, 10 partitions

Quarterly partitions plus (product, warehouse, time) for history lookups.

Slide 5 (about 60 seconds). Abridged DDL for the ledger. Three design decisions worth saying out loud. One: the primary key is (ledger_id, entry_time) because MySQL demands the partitioning column in every unique key. Two: no foreign keys, again because of partitioning, so trigger trg_ledger_bi does the checking. Three: the CHECK stops zero-quantity rows, and the table is partitioned by quarter with four secondary indexes. Slide 10 shows what that buys. If asked: the real DDL is in sql/01_schema.sql.
