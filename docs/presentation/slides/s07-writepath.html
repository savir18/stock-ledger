Slide 7 (about 60 seconds). The app account has no INSERT on the ledger at all; it can only EXECUTE procedures. This is the core of sp_record_movement. READ COMMITTED isolation, then lock the balance row with SELECT ... FOR UPDATE before checking stock, so two people selling the last units are serialized: the second waits, sees the reduced balance and is refused. Then INSERT into the ledger, the AFTER INSERT trigger updates the balance, COMMIT. An exit handler rolls back and re-signals on any error. Live demo: two mysql windows, window A holds the lock, window B hangs until A commits.
